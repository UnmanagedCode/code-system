## Gotchas (protocol/environment constraints, verified from cc's contract docs)

- [gotchas/bound-conformance.md](gotchas/bound-conformance.md) — the BOUND run (`npm run conformance:docker`): 48/11/4 of 63 IDENTICAL ON BOTH CHANNEL ARMS, 41 rows exercising the shipped docker transport, and the census of what the channel carried while doing it; `TMPDIR` redirects cc's fixture roots and survives its run isolation; a `-v` source is resolved by the DAEMON on the host (so `/tmp` is unbindable and the repo bind is not); `--user` is load-bearing for the EACCES row; `--pid=container:<self>` makes cc's cross-namespace SIGKILL honest and is REFUSED by default when the daemon rejects it (`CODE_SYSTEM_ALLOW_UNSHARED_PID=1` overrides), plus why sharing `/proc` is still safe; the two structural non-coverages; the transport DEFECT it found; why `ssh` does not inherit the result
- [gotchas/file-ops-over-exec.md](gotchas/file-ops-over-exec.md) — `readFile`/`writeFile` are derived over `exec`, not `docker cp`/`scp`; our own refusals carry a per-call nonce tag (matching the `strerror` tail is spoofable by a path); `exclusive` is `set -C`
- [gotchas/docker-channel.md](gotchas/docker-channel.md) — the held-open `docker exec … /bin/sh`: the cost removed is the SPAWN (84–95 ms → 2–7 ms per op); per-op reap granularity survives a SHARED channel only because the token rides as the command's env PREFIX (the channel shell's own environ carries none, and unmodified `buildReapScript` answers `CCREAP ok`); **dash OVER-READS its command stream**, so an exact byte count alone is not reachable and the ready marker is load-bearing; a missing table-row binary is `env` failing to exec — byte-identical on both paths — and the ONLY divergence is `env` itself; a channel shell dies with its host client while a running command does not; **the marker guarantees the payload ARRIVES, not that the op READS it** — every `buildWriteScript` refusal leaves the remainder in the channel's stdin and poisons a LATER, unrelated op, so a payload op that exits non-zero retires its channel (exit 0, never a size threshold); a `writeFile` is the one op that is slow AND silent on both streams, so the idle watchdog counts host-side stdin progress too; and cc DISCARDS a cleanly-exiting provider's stderr, so the drift alarm is unhearable without the bound runner's redirect seam
- [gotchas/no-persistent-shell.md](gotchas/no-persistent-shell.md) — the protocol has no long-lived shell at all; NOTHING carries over between commands, not even cwd; `stdin`/`stdinClose` are deleted frames and must be ignored, never refused
- [gotchas/baseline-probe-two-tier.md](gotchas/baseline-probe-two-tier.md) — the tooling probe is cached on a reachability fingerprint; check the flag not the binary; busybox `stat` succeeds and is wrong; the live busybox verdict is FOUR capabilities, not three
- [gotchas/docker-exec-transport.md](gotchas/docker-exec-transport.md) — measured `docker exec` behaviour: children survive their host client; a never-started command reports on STDOUT with exit 127/128 while daemon refusals use stderr; `processGroupSignal` could be `true` and why it is not; `env -i --` (dropping the `--` lets a frame env key hijack the cwd) and the HOME discriminator; `-i` iff `stdin:'pipe'`; no `ps` in `node:24-slim`; **`-u`**: a uid with no passwd entry is ACCEPTED and runs (so there is nothing cheap to pre-validate), a rejected one is exit 1 + empty stdout + `unable to find user|group`, and the reap script run unprivileged is NOT blind (`CCREAP ok 0 1`)
- [gotchas/ssh-controlmaster-transport.md](gotchas/ssh-controlmaster-transport.md) — measured `ssh` behaviour: exit 255 classifies NOTHING (a command's own 255 is indistinguishable); ssh takes a SHELL STRING so the far side's login shell re-parses it; `ControlMaster=auto` needs the control DIRECTORY and fails without it while `no` still multiplexes (which is why `spawnPlan` can stay pure); never emit `-M` (doubled it means `ask`); `-T` vs `RequestTTY force`; `-O check` speaks on stderr; the known_hosts policy is `ask` + `BatchMode`; **`ControlMaster=yes` over a LIVE ControlPath exits 0** — it degrades, re-authenticates and orphans a daemonised `ssh -N` (which is why `connect` pre-checks); a socket whose MASTER IS DEAD outlives it and is indistinguishable by stderr from a stray file

- [gotchas/mirror-advertisement.md](gotchas/mirror-advertisement.md) — cc MEMOISES the descriptor per connection generation (so the capability must be constant and a mirror edit is not live); `mirrorRoot: null` is a VALID descriptor, not a missing one; cc refuses to normalise a provider's path claim and why; `MIRROR_ROOT_EXCLUDES_PROJECT`/`MIRROR_EXCLUDE_COVERS_PROJECT` are 501s fired AT SPAWN while a shape refusal is a 502; containment is `path.posix.relative`, so `/app-backup` is not inside `/app`; the defaults come from §11's table, not from us

## Glossary

- **`systems-protocol.md §N`** — a section of **cc's** wire spec, cited throughout `src/`, `docs/`, `tests/` and here. The file is **not in this repo**: read it at `$CC_CHECKOUT/docs/systems-protocol.md` in a code-conductor checkout (`docs/protocol.md`).
- **System** (cc concept) — a transport row in cc's config; this plugin registers one per provider KIND (`docker`, `ssh`), not one per remote.
- **remote / `remoteId`** — the actual target machine or container. Config is stored per `remoteId`. This is the real "remote system"; the cc System is just how cc reaches it.
- **provider** — this plugin's code for one KIND of transport (`docker` or `ssh`), running on cc's host.
- **kind** — one transport implementation behind the `Transport` seam (`src/launcher/kinds/`): it builds argv and nothing else. `docker`, `ssh`, and `host` (the never-registered conformance vehicle).
- **ControlMaster / ControlPath** (ssh) — the multiplexed connection and the unix socket it lives on. The socket's existence is what `ssh`'s PROBE reports; it is **not** the gate (see [gotchas/gate-versus-probe.md](gotchas/gate-versus-probe.md)) — closing the master does not stop commands, it only un-multiplexes them.
- **gate** (`record.enabled`) — the operator's on/off switch for a remote, stored per `remoteId`. The only thing that decides whether an operation runs. Distinct from the probe, and **never called "connected"** — the MCP listing's word for a gate-off remote is `disabled`, and `tests/mcp.test.mjs` asserts it borrows no form of the verb.
- **probe** (`Transport.reachability`) — the live answer to "is the target there", re-asked on every card render and never cached or gated.
- **launcher** — the process cc spawns per System row (`src/launcher/main.mjs`). Owns the protocol for every kind.
- **baseline** — a per-remote verdict (`ok` / `unsupported` / `unknown`) on whether the target has the GNU tooling cc's derived operations need.
- **reap** — a kind's relay of the kill into the far side, for children that are not the launcher's OS descendants (`Transport.reap`). A `/proc` scan for the exec's `CC_EXEC_TOKEN`, shared by `docker` and `ssh` from `src/launcher/kinds/reapscript.mjs`.
- **`CC_EXEC_TOKEN`** — a per-exec nonce the core generates and the kind places in the far-side command's environment, so `reap` can find that exec's own processes.
- **identity / `config.user` (docker)** — the card's **Run as** field: the user (and optionally group) every docker action on that remote runs as, passed to `docker exec -u`. A **kind-owned config field** rendered in the card's Advanced group via the descriptor's `advanced: true` flag, not operator policy like the mirror — so it reaches every docker invocation the provider makes except `inspect` (exec, the derived file operations, the baseline probe, the kill relay), and **changing it resets the gate and the baseline**, which is the only thing that re-probes the tooling verdict as the new user. Empty means the image's default user and emits no flag at all. See [gotchas/docker-exec-transport.md](gotchas/docker-exec-transport.md) §7.
- **mirror advertisement / `mirrorRoot` / `exclude`** — what a provider tells cc, per remote, about the target's own geometry: `mirrorRoot` is how much of the target's filesystem cc's session root is the local image of, and `exclude` is the prefixes cc must never carry across. Answered on the `describeRemote` frame from `record.mirror`, set per card in the UI's **Advanced** group, and validated once by `src/mirror.mjs`. Advertising **nothing** (`mirrorRoot: null`) is a valid answer and is what every remote does until an operator opts in. See [gotchas/mirror-advertisement.md](gotchas/mirror-advertisement.md).
